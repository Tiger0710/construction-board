# 月またぎ入力の調査（2026-09-09）

対象: `d756ee4` 時点の入力・保存・サイネージ処理。月またぎ機能は未修正。本番への書込は実施していない。

## 結論

月をまたぐ開始日・終了日は入力できるが、案件を月に依存せず継続して編集する仕組みになっていない。
表示されなくなった案件を翌月に再登録すると別IDとなり、元データと併記される場合がある。
自動保存が案件を2つに分割するのではなく、保存先・読込範囲・別月の編集方法の不整合がある。

## ブラウザで再現した動作

`node tests/month-boundary-audit.cjs`: 7動作を再現。通信はすべてモック、PUTもモック内のみ。

- 9月30日～10月3日の案件を9月に登録しても、保存先は9月ファイルのみ。
- 実際の日付が9月の間は、10月画面に9月の案件が参照行として表示される。
- 10月の参照行をクリックすると、画面全体が9月へ戻る。その場で10月の日付を編集できない。
- 10月に同内容を追加すると新しいIDが付くため、元の参照行と合わせて2行になる。
- 元と同じIDの場合だけ、参照行の重複は抑止される。
- 実際の日付を10月1日に進めると、10月画面は9月ファイルを取得しない。
- 結果として、9月に登録した月またぎ案件が10月の入力表から見えなくなる。

## コード上の根拠

- `static/input.html` の `loadData`: 表示月に加えて取得するのは「実際の本日・明日の属する月」。表示月の前月ではない。
- `loadData` の `curIds`: 別月の案件はID一致でのみ排除。新規登録の同名案件は別行となる。
- `saveData`: `state.month` と `state.data` をそのまま1月分として保存。
- `onAdjClick`: `state.month` を元の月へ変更して画面を再読込。
- `saveProject`: 新規追加は常に `genId()` で別IDを作る。
- `netlify/functions/data.mjs` のサイネージ取得: 前月・当月・翌月だけを取得。2か月以上前のファイルに残した長期案件は対象外になり得る。
- サイネージの重複排除は日付・客先・工事件名・昼夜・会社/担当者等で判定し、作業内容・重点指定は比較しない。同条件の別月レコードに入力差があると、先に読んだレコードだけが残り得る。

## 推奨修正方針（未実施）

1. 1案件のIDと保存元を維持し、対象期間のどの月からでも同じ案件・日次データを編集できるようにする。
2. 取得対象を実際の本日・明日から切り離し、表示月に重なる全案件を取得する。単に前月を追加するだけでは長期案件をカバーできない。

実案件の同名・別IDが利用者の指摘そのものかは、該当案件の特定が必要。仕組みの不整合と再登録時の2行表示は再現済み。
